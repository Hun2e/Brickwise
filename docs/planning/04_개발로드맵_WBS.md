## 4. 테스트·평가 계획

### 4.1 평가 데이터셋 구축
| 세트 | 규모 (초기 목표) | 구축 방법 | 정답 검증 |
|---|---|---|---|
| **E-PLAN** 부품 분석 | 가짜 인벤토리 15케이스 + 실제 세트 조합 10시나리오 | 수작업 소형 케이스, 실제 조합은 pandas 독립 구현으로 기대값 산출 | 엔진 출력과 독립 구현의 완전 일치 |
| **E-ROUTE** 라우팅 | 60문항 (경로당 7~10) | PM이 작성, 한국어 표현 변형 포함 | 라벨 정확도, 혼동 행렬 |
| **E-RET** 검색 | 80문항 (한 60 · 영 20) | 세트·시리즈 문서에서 LLM으로 질문 초안 → PM 검수, 정답 청크 ID 라벨 | Recall@K, MRR, nDCG@5 |
| **E-ANS** 답변 | E-RET 중 40문항 + 답할 수 없는 질문 10 | 참조 답변 작성 (근거 청크 기반) | LLM 판정(정확도·Faithfulness) + PM 표본 검수 20% |
| **E-INT** 통합 | 30문항 (S4·S5·S6형) | 실제 컬렉션 시나리오 | DB 값과 답변 수치 일치율, 환각 번호 0건, 보유 정보 반영 여부 |
| **E-BASE** RAG 전후 | 대표 질문 ≥ 5 (환각이 쉬운 세트 사실·판본 비교) | 같은 질문을 LLM 단독과 서비스에 각각 질의 | 사실 정확성·근거 제시·모름 처리 3기준 (과제 4.6) |
