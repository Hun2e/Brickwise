# PRD — Brick Archive Planner (가칭)

> LEGO Group과 무관한 비공식 팬 프로젝트입니다. 서비스명은 LEGO 상표를 단독 명칭으로 쓰지 않는다는 원칙(L7)에 따른 가칭입니다.

- 작성: PM(Claude Code) · 2026-10-21 · 버전 0.1
- 근거 문서: [00_LEGO_1차기획검토.md](00_LEGO_1차기획검토.md), [02_데이터수집설계서.md](02_데이터수집설계서.md)
- 확정 결정: L1·L3·L4·L5·L6·L7 확정. **L2(Brickipedia)는 사용자가 Fandom 약관을 확인할 때까지 조건부**입니다. 쓸 수 없게 되면 §9의 대체 경로를 적용합니다.
- 일정과 팀 구성은 정해지지 않았으므로 이 문서에 쓰지 않습니다.

## 1. 제품 개요

| 비목표 | MOC 지원, 조립 설명서 제공·파싱, 이미지 인식, 가격·구매, 공식 한국어 제품명 생성 |

### 4.3 서비스 B — Build Planner
| ID | 요구사항 | 우선 |
|---|---|---|
| B-01 | 보유 세트 등록: 세트 번호(예: 75192 또는 75192-1)와 수량을 입력한다. 범위 밖이어도 Rebrickable에 있는 세트면 허용한다. 없는 번호는 거부하고 유사 후보를 제시한다 | M |
| B-02 | 보유 부품 집계: 각 세트의 최신 인벤토리에서 **스페어를 빼고 미니피그 구성 부품을 전개**한 뒤, `(part_num, color_id)`로 합산하고 보유 수량을 곱한다 | M |
| B-03 | 부품 보정: 사용자가 분실·추가 부품을 `(part_num, color_id, ±수량)`으로 입력한다 | S |
| B-04 | 목표 세트 부족 분석: `missing = max(0, need − have)`. 결과 표는 부품 번호·부품명·색상·필요·보유·부족, 그리고 합계(부족 개수, 부족 종류 수, 커버리지 %) | M |
| B-05 | 매칭 모드(L5): `exact`(기본), `ignore_color`, `mold_variant`(관계 유형 M·A만 허용). 대체 결과는 "대체 사용" 표시와 별도 합계로 보여 준다. 인쇄 관계(P)는 대체하지 않는다 | M(exact·ignore_color) / S(mold_variant) |
| B-06 | 추천: 범위 세트(또는 사용자 조건 필터 결과)를 대상으로 부족 개수 → 부족 종류 수 → 커버리지 → 연도 순으로 상위 N개를 보여 준다. 보유한 세트 자체는 제외한다 | M |
| B-07 | 추천·분석 결과의 세트마다 설명서 링크(LEGO 공식 페이지 URL만)와 상태 배지(링크 확인됨/미확인)를 붙인다 | S |
| B-08 | 사용자 컬렉션은 브라우저 세션 기준으로 저장하고, 서버 SQLite에 익명 컬렉션 ID로 보관한다 (로그인 없음) | M |
| B-09 | Rebrickable 사용자 컬렉션 가져오기 (사용자 본인 API 키) | L |

## 5. 사용자 스토리와 수용 기준

| 스토리 | 수용 기준 (Given / When / Then) |
|---|---|
| US-1 (P2) 세트의 특징을 근거와 함께 알고 싶다 | Given 75192-1 선택 · When "특징 알려줘" · Then 답변 주장마다 `[근거 N]`, 근거 목록에 인용된 것만 표시, Brickipedia 근거에 CC-BY-SA 표기와 원문 링크 |
| US-2 (P2) 팔콘 판본 비교 | When "팔콘 연도별 비교" · Then 비교 표의 모든 숫자가 DB 값과 일치(자동 테스트), 범위 밖 구판은 "비교 전용" 표시 |
| US-3 (P1) 조건 탐색 | When "2018년 이후 1,000개 이상" · Then 결과 전부가 year≥2018 ∧ num_parts≥1000, 적용된 필터가 화면에 보임, 카드를 누르면 해당 세트 대화로 이동 |
| US-4 (P1/P3) 보유 세트 등록 | When 75192 ×2 등록 · Then 보유 부품 합계 = (num_parts) × 2 와 일치 (스페어 제외, 미니피그 포함 기준) |
| US-5 (P3) 부족 부품 | When 목표 75301-1 분석 · Then 부족 표의 합계 = Σmax(0, need−have), 색상이 다른 같은 부품은 별도 행 |
| US-6 (P1) 부족 최소 추천 | When 추천 요청 · Then 상위 N개가 정렬 기준대로 정렬, 보유 세트는 제외, 각 결과에 부족 개수 표시 |
| US-7 (P1) 결합 질문 | When S5 질문 · Then 선택된 세트가 추천 목록 안에 실제로 있고, 설명은 그 세트의 근거만 인용 |
| US-8 존재하지 않는 세트 | When "99999 세트 알려줘" · Then "데이터에 없는 세트" 안내, 생성 답변 없음 |

## 6. 주요 화면과 사용자 흐름

> **개정 (2026-10-22, ADR-018)**: 이 절의 탭 3개(아카이브·내 컬렉션·탐색) 화면과 세트별 thread 흐름은 **대화 중심 챗봇 UX**로 바뀐다. 단일 대화창·현재 대상 바·대화 안 카드·보조 패널(세트별 기록)로 구성한다. 상세: `docs/planning/05_대화UX설계.md`. 아래 원문은 이력으로 남긴다.


### 화면 구성 (Vanilla UI 기준. Streamlit은 같은 기능을 탭으로 구성)
1. **헤더**: 서비스명, 비공식 고지, 탭(아카이브 / 내 컬렉션 / 탐색)
2. **아카이브 탭**: 왼쪽 세트 검색·선택(한·영 별칭 검색) → 가운데 채팅(진행 상태 단계 표시) → 오른쪽 근거 패널(유형 배지, 제목, 링크, 라이선스)
3. **내 컬렉션 탭**: 세트 번호·수량 입력, 보유 목록, 부품 합계, 보정 입력(S) → "목표 분석" 입력 → 부족 표 → "추천 받기"(조건 + 모드 선택) → 추천 카드(부족 개수, 커버리지 막대, "이 세트 알아보기" → 아카이브 대화)
4. **탐색 탭**: 자연어 조건 입력 → 적용 필터 칩(수정 가능) → 세트 카드

### 흐름
```
[탐색] 조건 입력 → 카드 → [아카이브] 세트 대화
[컬렉션] 세트 등록 → 추천 → 카드 "알아보기" → [아카이브] 대화 (보유 문맥 유지)
[아카이브] "내 세트로…" 질문 → 라우터(build_archive) → 컬렉션 계산 → 근거 설명
```

| `POST /api/chat` | `{set_num, message, history_id, collection_id?}` | `{answer, citations[{n, source_type, title, url, license}], route, warnings[]}` |
| `POST /api/search` | `{query}` | `{filters, items[]}` |
| `POST /api/collections` / `PUT /api/collections/{id}` | `{sets[{set_num, qty}], adjustments[]}` | `{id, total_parts, lots}` |
| `POST /api/build/analyze` | `{collection_id, target_set_num, mode}` | `{missing[], totals{missing, lots, coverage}}` |

- 진행 상태는 `POST /api/chat`의 SSE 스트림(`stage` 이벤트) 사용을 권장합니다(S). 어려우면 단계별 폴링으로 대체합니다.

## 8. 예외 상황
| 상황 | 처리 |
|---|---|
| 세트 번호 형식 오류·없는 세트 | 입력 정규화(`75192` → `75192-1`), 없으면 유사 후보 제시, 생성 금지 |
| 인벤토리가 없는 세트 (범위 내 약 1.3% [확인]) | "부품 목록 미보유" 표시, 분석 대상에서 제외 |
| 인벤토리 판본이 여러 개 (범위 내 13세트 [확인]) | 최신 version 사용, 화면에 판본 표시 |
| 부품이 충분해도 설명서 링크 미확인 | "설명서 미확인" 배지, 조립 가능 판정과 분리 |
| 색상 불명(color_id = -1) | exact 모드에서 매칭 불가로 계산하고 표시 |
| 문서 수집 실패·429 | 재시도 후 캐시된 문서로 답변, 실패 안내 |
| 근거 없음 | "문서에서 확인되지 않습니다" + 인용 없음 안내 |
| 숫자 검증 실패 | 해당 문장 제거 + "검증되지 않은 수치를 제외했습니다" 경고 |
| 키 누락·색인 0건 | 상태 패널 안내, 기능 비활성 |

## 9. Brickipedia 사용 불가 시 대체 경로 (L2 조건부)
1. 세트 문서 = **DB 기반 템플릿 설명문**(연도, 서브테마, 부품 수, 미니피그 목록, 같은 기체 판본 목록)으로 바꾸고, `source_type=db`로 표시합니다.
2. 서술형 문서 = 위키백과(영·한)의 시리즈·기체 문서만 씁니다.
3. "세트별 특징" 질문은 위키 근거가 없으면 판정을 보류합니다. 이에 따라 PRD의 US-1 수용 기준을 조정합니다.

## 11. 평가와 출시 기준 (MVP 완료 정의)
| 영역 | 지표 | MVP 기준 (초기 목표) |
|---|---|---|
| 부품 분석 | 집계·부족 계산 정확도 | **100%** (결정적 정답 테스트) · `num_parts` 재현 331/332 이상 |

| 교차 언어 | 한국어 질의 Recall@5 / 영어 질의 Recall@5 | 비율 보고 (① 원문 vs ② 질의 번역) |
