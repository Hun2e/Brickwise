## 데이터 규칙 (반드시 지킬 것)
1. **스키마**: `docs/planning/02_데이터수집설계서.md` §4.1을 따른다. 원본 12테이블은 CSV 컬럼 그대로 둔다. 실측한 컬럼은 다음과 같다.
   - themes(id,name,parent_id)
   - colors(id,name,rgb,is_trans,num_parts,num_sets,y1,y2)
   - part_categories(id,name)
   - parts(part_num,name,part_cat_id,part_material)
   - part_relationships(rel_type,child_part_num,parent_part_num)
   - elements(element_id,part_num,color_id,design_id)
   - sets(set_num,name,year,theme_id,num_parts,img_url)
   - minifigs(fig_num,name,num_parts,img_url)
   - inventories(id,version,set_num)
   - inventory_parts(inventory_id,part_num,color_id,quantity,is_spare,img_url)
   - inventory_sets(inventory_id,set_num,quantity)
   - inventory_minifigs(inventory_id,fig_num,quantity)
   - 인덱스: `inventory_parts(inventory_id)`, `inventories(set_num)`, `sets(theme_id)`, `sets(year)`, `set_parts_flat(part_num, color_id)`
2. **불리언**: `is_spare`, `is_trans`는 CSV에서 `True/False` 또는 `t/f`로 올 수 있다. 0/1 정수로 정규화한다.
3. **메모리**: inventory_parts(약 157만 행)는 스트리밍(gzip + csv 모듈, `executemany` 배치)으로 적재한다. 전체를 한 번에 메모리에 올리지 않는다. 새 의존성을 추가하지 않는다 (표준 라이브러리만 사용, pandas 사용 금지).
4. **set_root_theme**: `themes.parent_id`를 따라 최상위 테마를 찾는다. `subtheme_name` = 세트의 직속 테마명.
5. **set_parts_flat** (부품 집계 정의 — 가장 중요)
   - 세트마다 `inventories.version`이 가장 큰 인벤토리 1개만 쓴다.
   - `is_spare = 1` 행은 제외한다.
   - 미니피그 전개: `inventory_minifigs(inventory_id, fig_num, quantity)`의 `fig_num`을 `inventories.set_num = fig_num`인 인벤토리(역시 최신 version)의 부품으로 전개한다. 부품 수량 × 미니피그 수량, 스페어는 제외한다.
   - `(set_num, part_num, color_id)`로 합산한다 (PK).
   - 범위 제한 없이 **모든 세트**에 대해 만든다 (T-002 추천 후보가 범위 밖일 수 있음).
   - 검증 기준: 스타워즈 core 범위 332세트 중 **331세트 이상**에서 `Σquantity == sets.num_parts` (PM 실측: 331/332).
6. **set_scope**: 값은 settings에서 읽는다. 다음 키를 settings.yaml에 추가한다.
   ```yaml
   rebrickable:
     base_url: "https://cdn.rebrickable.com/media/downloads/"
     csv_dir: "data/raw/rebrickable"
   scope:
     root_theme: "Star Wars"
     year_min: 2015
     year_max: 2026
     parts_min: 100
     parts_max: 1500
     compare_keywords: ["Millennium Falcon", "X-wing", "TIE", "AT-AT", "Star Destroyer"]
     compare_parts_min: 100
   ```
   - core = 루트 테마 일치, 연도 범위, `num_parts` 범위, 그리고 `set_parts_flat`에 행이 있는 세트 (PM 실측: 332)
   - compare_only = core가 아니고, 루트 테마가 같고, 이름에 compare_keywords 중 하나를 포함하며(대소문자 무시), `num_parts >= compare_parts_min`이고, 부품 목록이 있는 세트
7. **경로**: 모든 경로는 리포 루트 기준이다 (`config.project_root()`). 하드코딩하지 않는다.

- 설계 판단과 이유:
  - gzip/csv 이터레이터와 `executemany` 배치(`rebrickable.batch_size=10000`)로 적재하고, 12종 CSV를 정상 적재한 임시 DB만 목적 파일로 교체함. 헤더 변경·손상·누락 시 기존 DB를 보존함.
  - 원본 참조 누락을 진단할 수 있도록 FK 강제 제약 대신 명시적 검사로 보고함. inventory_id 누락은 실패, part_num/color_id 누락은 지시서대로 정보성 결과이며 각각 건수·예시 최대 5개를 출력함.
  - 최신 인벤토리는 `version DESC, id DESC`로 1개를 선정함. 동일 버전 동률에도 결정적이며 최신 인벤토리에 부품이 없어도 과거 판본으로 대체하지 않음. 미니피그 구성품을 수량 곱으로 전개한 뒤 일반 부품과 합산하고, `inventory_sets`는 요구된 집계 정의에 없어 전개하지 않음.
