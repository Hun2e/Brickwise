## 목표
1. PM이 검증한 규칙표(`config/entity_rules.yaml`)로 **세트 → 기체·캐릭터·장소 문서**를 결정적으로 매핑한다.
2. 한국어 별칭 사전을 만든다.
3. 세트마다 항목 텍스트 1개를 만들어 Chroma `set_meta` 컬렉션에 색인한다.

이 매핑은 T-006(기체 문서 청크의 `sets` 배열)과 T-007(사전 수집 대상)의 입력이 된다.

## 설계 결정 (검토 포인트 ①~⑤)

### ① 매핑 결과 저장 위치
- `set_entities(set_num, wiki_title, kind, rule_index)`와 `ko_aliases`는 **`lego.sqlite`의 파생 테이블**로 둔다.
- `lego.sqlite`는 적재 때 통째로 교체되므로 `scripts/build_entities.py`로 언제든 다시 만들 수 있게 한다.
- 실행 순서: `load_rebrickable.py` → `build_entities.py` → `index_items.py`. 이 순서는 README와 스크립트 도움말에 적는다.
- `build_entities.py`는 순수 계산(규칙 × 세트명)이므로 네트워크가 필요 없다.

### ② 매핑 규칙 적용
- 대상은 `set_scope`의 core + compare_only 세트다.
- 규칙마다 `re.search(pattern, sets.name, re.IGNORECASE)`로 매칭하고, 매칭된 모든 규칙의 `wiki_title`을 중복 없이 넣는다.
- `kind: list` 규칙은 `entity_rules.yaml`의 `include_list_pages`가 true일 때만 적용한다 (현재 false).
- 매칭이 없는 세트는 `set_entities`에 행이 없다 → 검색 시 시리즈 문서만 쓴다 (ADR-008).
- PM 실측: core 332세트 중 **249세트(75.0%)** 매핑, 세트당 평균 0.93개, 최대 3개. 이 수치를 테스트 기대값으로 쓴다 (데이터 갱신 시 변동 허용 범위는 ±5).

### ③ 한국어 별칭 사전 (`ko_aliases`)
| 출처 (`source`) | 내용 | `verified` | 용도 |
|---|---|---|---|
| `wiki_langlink` | 규칙표 `ko_title` (PM이 위키 언어 링크로 확인한 45개) | 1 | 화면 표기 + 검색 |
| `manual` | `config/ko_aliases_manual.yaml`의 수작업 별칭 | 파일에 명시 | verified=1이면 화면, 0이면 검색 확장만 |

- 컬럼: `alias`, `canonical_en`(= wiki_title), `kind`, `source`, `verified`. PK는 `(alias, canonical_en)`이다.
- LLM으로 음역 후보를 만드는 기능은 이번 범위가 아니다.
- 수작업 별칭 초기값 (검토 대상):

  | alias | canonical_en | verified | 비고 |
  |---|---|---|---|
  | 밀팔 | Millennium Falcon | 0 | 커뮤니티 은어 (T-004에서 P1이 해석함) |
  | 팔콘 | Millennium Falcon | 0 | 영어 발음 표기 |
  | 엑스윙 | X-wing fighter | 0 | 위키 표기는 "X-윙" |
  | 타이파이터 | TIE fighter | 0 | 띄어쓰기 변형 |
  | 스톰트루퍼 | Stormtrooper | 0 | 위키 한국어 링크 없음 |
  | 만달로리안 | Mandalorian (character) | 0 | 캐릭터 문서는 한국어 링크 없음 |

### ④ 항목 텍스트 형식 (ADR-008 결정 4)
```
세트: Millennium Falcon (75257-1)
별칭: 밀레니엄 팰컨
검색어: 밀팔, 팔콘
연도: 2019 · 테마: Star Wars · 공식 부품 수: 1,328개
미니피그(6): Boolio, C-3PO, Chewbacca, Finn, Lando Calrissian, R2-D2
관련: Millennium Falcon
```
- `별칭`에는 verified=1만, `검색어`에는 verified=0을 넣는다 (화면에는 별칭만 노출).
- 미니피그 이름은 최신 인벤토리 기준 `inventory_minifigs` → `minifigs.name`에서 짧은 이름을 뽑는다 (검토 포인트 ⑥). 같은 짧은 이름이 여러 개면 1번만 쓰고 개수는 합산하며, 이름순으로 정렬한다.
- `공식 부품 수`는 `sets.num_parts`를 쓴다 (T-001 결정: 화면 표기는 공식값).
- `관련`에는 `set_entities`의 wiki_title을 쓴다 (없으면 줄 생략).
- **같은 기체 다른 판본 목록은 넣지 않는다** (ADR-008).
- Chroma 메타데이터: `source_type="set_meta"`, `set_num`, `name`, `year`, `theme`, `num_parts`, `num_minifigs`, `scope`, `entities`(list[str], 없으면 넣지 않음), `has_ko_alias`(bool)

### ⑤ 임베딩과 색인
- 임베딩 캐시: `data/collected/embed_cache.sqlite`, 키는 `sha256(model + "\n" + text)`, 값은 float 배열(JSON 또는 BLOB)이다. 캐시에 있으면 API를 호출하지 않는다.
- 배치 크기는 settings `index.embed_batch_size`(기본 64)다.
- 색인: `langchain_chroma.Chroma`(persist_directory `data/chroma`, collection `set_meta`)에 `ids=set_num`으로 upsert한다 (PM 확인: `add_texts`가 upsert로 동작).
- **멱등**: 두 번 실행해도 컬렉션 건수는 같다. 세트가 범위에서 빠지면 그 ID를 삭제한다 (현재 범위와 컬렉션 ID 집합을 비교).
- 리포트: 색인 건수, 신규/갱신/삭제 수, 임베딩 API 호출 수, 캐시 적중 수, 소요 시간.

### ⑥ 미니피그 짧은 이름 (PM 실측으로 추가된 검토 포인트)
- 원본 이름은 변형 설명이 붙은 긴 형식이다. 75257-1 예:
  - `Chewbacca, Dark Brown - Long Lines on Legs on Inside`
  - `Astromech Droid, R2-D2, Flat Silver Dome, Dark Blue Print with Lavender Dots`
  - `Lando Calrissian, Old, Dark Azure and Black Cape`
- 규칙 (초안): 쉼표로 나눈 **첫 조각**을 쓰되, 첫 조각이 일반 명칭 목록(`Astromech Droid`, `Battle Droid`, `Protocol Droid`, `Clone Trooper`, `Stormtrooper` 등 — 설정 `index.generic_minifig_prefixes`)이면 **두 번째 조각**을 쓴다.
  - 결과: Chewbacca / R2-D2 / Lando Calrissian
- 원본 전체 이름은 메타데이터에 넣지 않는다 (텍스트 길이·임베딩 희석 방지).
- 테스트: 위 3개 예시 + 일반 명칭만 있는 경우(`Clone Trooper, Phase 2` → 두 번째 조각이 변형 설명이면?) — **두 번째 조각이 색상·변형 설명으로 보이면 첫 조각을 쓴다**. 판별이 애매하므로 규칙을 단순하게 유지하고, 실데이터 표본 30개를 결과 보고에 출력해 PM이 검수한다.

### 설계 판단과 이유

- 목록 문서는 계속 제외하고 미매핑 core 83세트는 유지했다. 규칙 순서와 wiki_title 중복 제거를 지키고, 범위를 줄여 재생성하면 이전 매핑도 제거한다.
- 별칭 PK 충돌에서는 위키 언어 링크를 우선한다. 검수 별칭은 `별칭`, 미검수 별칭은 `검색어`로 나눈다. 전체 규칙표의 검수 별칭 45개를 보존하되 항목에는 실제 연결된 문서의 별칭만 사용한다.
- 미니피그는 version 내림차순·동일 version에서는 ID 내림차순으로 최신 인벤토리를 정한다. 짧은 이름으로 중복 제거·이름순 정렬하고 수량 합계를 괄호에 표시한다. 공식 부품 수는 `sets.num_parts`를 사용한다.
- 캐시는 `sha256(model + "\n" + text)`를 키로 JSON float 배열을 저장한다. 중복 미적중 텍스트는 한 번만 임베딩하며 캐시 적중으로 과대 집계하지 않는다. 성공한 배치는 즉시 저장하여 후속 배치 실패 후 재실행에도 재사용한다. 빈 벡터·응답 수 불일치·NaN은 저장하지 않는다.
- Chroma upsert가 기존 메타데이터를 병합하므로 새 문서에서 사라진 필드에는 `None`을 전달하여 제거한다. 모든 upsert가 성공한 뒤 범위 이탈 ID를 삭제한다. Chroma 허용 배치 크기와 설정의 임베딩 배치 크기는 별도로 적용한다.
- 기존 LLM 팩토리의 `.env` 자동 로드 경로를 호출하지 않고 환경변수 및 기존 llm 설정으로 임베딩 클라이언트를 구성한다. `check_embedding_ctx_length=False`로 토크나이저 자료 다운로드를 피한다. 출력 통계의 `api_calls`는 캐시 래퍼가 호출한 임베딩 배치 횟수이며 SDK 내부 HTTP 재시도 횟수까지 세지는 않는다.
- 작업 중 동일 파일에 들어온 동시 편집을 확인하여 사용자에게 알렸고, 추가된 검증을 보존해 통합했다. 중복 추가된 YAML 설정은 한 벌로 정리했다.
