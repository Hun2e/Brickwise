# T-025 Vanilla 웹·Streamlit 대화 중심 화면

- 상태: 완료 (2026-10-23)
- 관련 요구사항: F2009, F2011, F2012, F2013, NF2004, ADR-018 ①⑥
- 선행 작업: T-024

## 목표
탭을 없애고 **하나의 대화창** 중심으로 웹과 Streamlit을 바꾼다. 두 UI는 같은 공통 서비스(T-024)를 쓰고, 대표 시나리오 7단계가 두 화면에서 똑같이 동작해야 한다.

## 화면 요소 (05 §2.1)
- 헤더: 서비스명, 상태 배지, [새 대화]
- **현재 대상 바**: 세트 라벨 + [변경](세트 검색 상자) + [해제]. 대상이 없으면 "대상 없음 — 바로 질문해도 돼요"를 보여 준다.
- 대화 영역
  - 질문, 진행 단계(StageTracker), 답변 핵심 문장, 경고 한 줄
  - **카드 목록**(`items`, 번호 배지): [이 세트로 질문] → `PATCH subject`, [보유 등록] → 등록 요청(같은 멱등 키 규칙)
  - "상세 표"(접힘), 처리 정보(접힘)
  - 되묻기는 선택 버튼으로 보여 준다(누르면 같은 대화로 응답 전송).
- 보조 패널
  - 대화 목록(제목·시각, 선택하면 복원)
  - 내 컬렉션(기존 편집기 + version 충돌 안내)
  - **세트별 기록**(현재 대상의 `set_history`, 비교 턴 배지)
- 근거 패널·`[근거 N]` 연동, 반응형(좁은 화면은 보조 패널 토글, 근거는 답변 아래)은 유지한다.

## 범위
- 포함
  1. `web/index.html`, `web/css/app.css`
  2. `web/js/state.js`: 상태를 `{uid, conversationId}`로 바꾼다. 구 `{selectedSet, activeTab}`는 읽어서 버리고, 레거시 대화가 있으면 그 대화를 연다.
  3. `web/js/api.js`(새 엔드포인트, `request_id`=`crypto.randomUUID()`, 재전송 시 같은 ID 유지)
  4. `web/js/render.js`(카드·되묻기 버튼·대상 바·세트별 기록), `web/js/app.js`
  5. `app_streamlit.py`
     - 같은 구조(사이드바=보조 패널, 본문=대화)
     - `?uid=&conv=` 복원
     - 입력 제출 시 세션에 `request_id`를 발급하고 rerun에서 재사용한다.
     - 카드 버튼은 `on_click`으로 대상을 변경한다.
  6. 테스트: `web/tests/*.test.mjs`, `tests/test_web_static.py`(탭 3개 검사를 대상 바·대화 구조 검사로 교체), `tests/test_streamlit_app.py`
     - 기존 F2009·F2011 의미 검증은 새 화면 계약으로 바꾸고, 삭제하지 않는다.
  7. **선행 정리 (T-024 리뷰에서 넘어온 것, 서비스 최소 수정 허용)**
     - `services/chat.py`: 해석한 대상이 있는 RAG 경로에는 대상 세트 번호·이름을 넣어 다시 쓴 질문을 P1·P3에 넘긴다. 저장·표시는 원문 그대로 한다. 테스트: "첫 번째 건 어떤 기체야?" → P3 질문에 "75535-1 Han Solo"가 들어간다.
     - 템플릿의 한국어 조사(을/를, 이/가, 은/는)를 받침에 따라 고르는 헬퍼(`rag/templates.py`).
     - `chat_requests` `running` 만료: settings `chat.request_timeout_sec`(기본 300)가 지나면 `failed`로 보고 재요청을 허용한다.
- 제외: 그 밖의 서비스·API 변경(필요하면 남은 이슈로), 디자인 시스템 교체(기존 토큰·색 유지, 레이아웃만 개편)

## 완료 기준 (DoD)
- [ ] 세트를 고르지 않고 첫 질문을 보낼 수 있다(웹·Streamlit).
- [ ] 대표 시나리오 7단계가 탭 이동·세트 번호 재입력 없이 진행된다(대역 API로 node·AppTest, 실제 키 실측은 T-026).
- [ ] 카드 [이 세트로 질문]은 화면 이동 없이 대상 바만 바꾼다(F2011). [보유 등록]은 변경 전후 수량을 보여 주고, 두 번 눌러도 한 번만 반영된다.
- [ ] 새로고침하면 같은 대화·대상·목록·pending이 복원되고, 다음 질문 "첫 번째 건"이 이어진다.
- [ ] 세트별 기록 패널: 대상을 A → B로 바꾸면 B 기록만 보이고, 비교 턴에는 배지가 붙는다(F2009·4.4 캡처 준비).
- [ ] 서버에서 받은 문자열은 innerHTML을 쓰지 않고, 외부 CDN이 없다(기존 정적 검사 유지). 360px에서 가로 스크롤이 없다.
- [ ] Streamlit 화면은 `rag_service.services` 공개 함수만 import한다.
- [ ] `node --test web/tests/*.test.mjs`와 `.venv\Scripts\python -m pytest -q` 전체 통과

- 설계 판단과 이유:
  - 탭을 제거하고 대화 ID를 기준으로 복원한다. 웹 저장 상태는 `{uid, conversationId}`, Streamlit URL은 `?uid=&conv=`다. 세트별 기록은 통합 타임라인과 별도로 공통 서비스/API에서 읽는다.
  - 카드 등록은 별도 컬렉션 쓰기 경로를 만들지 않고 동일 대화에 등록 질문을 보내 `chat_turn_v2`의 멱등 처리를 사용한다. 같은 카드와 실패 요청은 ID를 유지하며, 성공한 카드의 중복 클릭은 추가 제출하지 않는다.
  - 컬렉션 편집 스냅샷의 version을 저장 시 전달한다. 대화로 보유 목록이 바뀌어도 작성 중인 내용을 최신 version으로 몰래 덮어쓰지 않으며, 충돌 시 명시적으로 다시 불러오게 한다.
  - `chat.py`가 DB에서 읽은 대상 번호·이름으로 `rag_question`을 구성하고, 내부 `ResolvedContext`로 전달한다. 분류·템플릿·저장에는 원문을 유지하고 실제 RAG 호출에만 보완 질문을 전달한다. 공개 API·저장 스키마·라우팅 규칙은 변경하지 않았다. `75535-1 Han Solo` 회귀와 원문 보존을 검증했다.
  - `particle()`은 한글 종성으로 을/를·이/가·은/는 등을 선택한다. 숫자는 한국어 독음, 영문은 끝 글자 기준으로 처리한다. 대상 선택 문장과 공통 부품 문장에 연결했다.
  - `chat.request_timeout_sec: 300`을 추가했다. 같은 사용자·대화의 만료된 running 요청은 예약 트랜잭션에서 failed로 전환하고, 재예약 시 시작 시각을 갱신한다. 저장된 턴은 기존 방식으로 재전송한다.
