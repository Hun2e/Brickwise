# T-016 평가셋·채점·지연 측정 스크립트

- 상태: 완료 (2026-10-22)
- 관련 요구사항: F2014·F2015 실험 기반, F2002·F2006(검색 품질 근거), NF2001(응답 시간), 설계문서 "검증 결과" 재료

## 목표
T-017(검색 실험)·T-018(RAG 전후 비교)·T-019(회귀 확인)가 같은 잣대로 숫자를 낼 수 있게 평가셋 형식과 채점·측정 스크립트를 만든다. 문항 내용의 최종 확정은 PM이 한다.

## 범위
- 포함
  1. **평가 파일 형식** (`eval/README.md`에 스키마 설명)
     - `eval/retrieval.jsonl` — 검색 40문항
     - `eval/routing.jsonl` — 라우팅 40문항 (**PM 작성**, Codex는 형식 검증기만)
     - `eval/rag_compare.jsonl` — RAG 전후 8문항 (**PM 작성**, T-018에서 사용)
  2. **검색 문항 초안 생성기** `scripts/eval_draft_retrieval.py`: 고정 색인에서 (세트, 문서, 섹션)을 층화 추출하고, LLM이 그 섹션으로 답할 수 있는 질문 초안을 만든다 → `eval/drafts/retrieval_draft.jsonl`. PM이 검수해 `eval/retrieval.jsonl`로 옮긴다.
  3. **색인 스냅샷** (`.gitignore`에 `data/eval_snapshot/` 추가) `scripts/eval_snapshot.py`: 현재 `data/chroma`를 `data/eval_snapshot/<이름>/`로 복사하고 청크 수·문서 수·설정 해시를 매니페스트로 남긴다(git 제외).
  4. **검색 채점** `scripts/eval_retrieval.py`: 스냅샷 + 검색 설정(settings 또는 `--override key=value`)으로 각 문항을 검색해 Recall@k·MRR·문서 단위 적중률·언어별 분할을 낸다.
  5. **라우팅 채점** `scripts/eval_routing.py`: 정확도, 혼동 행렬, 틀린 문항 목록.
  6. **지연 측정** `scripts/eval_latency.py`: 경로별 대표 질문을 N회 실행해 중앙값·p90·단계별 시간(`timings`)을 낸다.
  7. 공통 결과 형식: `eval/results/<날짜>_<실험명>.json`(원자료) + `.md`(요약 표). 결과 파일은 git에 넣는다(설계문서 근거).
  8. 테스트: 채점 함수(Recall·MRR·라벨 매칭), 형식 검증기, 스냅샷 매니페스트 — 대역 데이터로.

  - 라우팅·RAG 전후 문항 작성(PM), 검색 문항 최종 검수(PM)

## 검토 포인트 결정 (사용자, 2026-10-22 — 6건 모두 권장안)
1. **검색 문항**: LLM 초안 60개 → PM이 검수해 40개를 고른다.
   - 생성 프롬프트에는 "섹션 문장을 그대로 옮기지 말고 사용자가 물을 법한 말투로"를 넣는다.
   - 초안에 섹션 본문과 질문의 최장 공통 부분 문자열 비율을 함께 기록한다. PM은 이 값을 탈락 판단에 참고한다.
2. **평가 색인**: 스냅샷을 고정한다. 평가 스크립트는 스냅샷 경로의 Chroma만 열고 **수집 함수를 연결하지 않는다**(`collect_fn=None`). 결과 파일에 스냅샷 매니페스트를 함께 기록한다.
3. **P1 확장어**: 실제와 같이 포함하되 문항별로 1회 생성해 `eval/cache/en_terms.jsonl`(키 = 문항 id + 질문 해시 + P1 버전)에 고정한다. 이후 모든 실험은 이 파일을 읽는다. 캐시 파일은 git에 넣는다(재현성).
4. **주 지표**: 섹션 단위 Recall@5. ADR-016 ④의 교체 기준(+3%p)이 이 값에 적용된다. MRR·문서 단위 Recall@5·Recall@1·3은 보조 지표다. 40문항에서 1문항은 2.5%p이므로, 보고서에 **문항 수 차이**도 함께 적는다.
5. **지연**: 두 조건으로 측정한다.
   - `warm`: 캐시 있음(실사용)
   - `cold`: LLM 캐시 우회
   - 우회는 settings `llm.cache_enabled`(기본 true)를 `--override`로 끈다. 서비스 기본 동작은 그대로다. 임베딩 캐시와 수집 캐시는 두 조건 모두 유지한다(외부 위키 재요청 방지, NF2006).
   - 경로별 대표 질문은 각 3회 실행한다.
6. **라우팅 40문항**: PM이 Codex 작업과 병행해 `eval/routing.jsonl`을 작성한다. Codex는 이 파일을 열지 않는다. 형식 검증과 채점은 기존 `route_questions.jsonl`로 확인한다.

- 설계 판단과 이유:
  - Recall은 고유 정답 라벨 회수율을 문항별 매크로 평균. 문서 지표는 doc_id를 중복 제거한 분모를 사용. 섹션은 명세대로 문자열 접두어 매칭. 적중 문항 수/완전 회수 문항 수를 별도로 기록하며 `--baseline`은 같은 문항·정답·스냅샷·P1 확장어일 때만 %p 및 문항 수 차이를 계산.
