## 목표
LLM 없이 결정적으로 동작하는 **DB 질의 계층**을 만든다.
- 사실 조회, 조건 필터, 두 세트 부품 비교, 판본 비교의 결과를 근거 카드(`source_type="db"`)로 바꾼다.

## 설계 (검토 포인트 ①~⑤)

### ① fact 템플릿이 무엇을 답하나
라우터는 경로만 알려 주고 "어떤 속성"인지는 알려 주지 않는다.
- (a) **세트 개요 템플릿 + 키워드로 주 속성 강조** [초안 권장]
  - 공식 부품 수·출시 연도·서브테마·미니피그 목록을 모두 담은 개요를 답한다.
  - 질문에 "부품/조각/몇 개", "연도/출시/언제", "미니피그/피규어/누가 들어" 같은 키워드가 있으면 그 속성을 첫 문장으로 올린다.
  - 키워드가 없으면 개요만 답한다.
- (b) LLM으로 속성 추출 — 정확하지만 템플릿을 고른 취지(LLM 없음·빠름)와 어긋난다.
- 예: "75192-1의 공식 부품 수는 7,541개입니다. [근거 1] · 출시 2017년 · Ultimate Collector Series · 미니피그 N명(…)"

### ② 판본 비교의 변형 표지와 중복 판본
- 변형 표지(설정 `compare.variant_markers`, 대소문자 무시, 단어 경계)
  - 초안: `microfighter`, `cockpit`, `diorama`, `mini`, `midi`, `bag charm`, `key chain`, `magnet`, `bust`, `helmet`, `polybag`, `mech`, `battle pack`
  - **`20th anniversary`는 넣지 않는다** (재출시 판본이므로 비교에 포함).
- 같은 판본 묶기: 세트 번호 앞부분(하이픈 앞)이 같고 연도·부품 수가 같으면 1행으로 묶고 변형 번호를 병기한다 (예: `4504-1/-2 (Blue/Black Box)`).
- 비교 대상 = 선택 세트의 엔티티(`set_entities`) 중 **vehicle** 엔티티의 연결 세트 (core + compare_only)
  - 선택 세트에 vehicle 엔티티가 없으면 이름 키워드로 대신하고 `warnings`에 남긴다.
- 표 열: 세트 번호 · 이름 · 연도 · 공식 부품 수 · 미니피그 수 · 서브테마 · 범위(core/compare_only)
  - 정렬은 연도 오름차순이다.
  - 빠진 변형은 "기타 변형 N개: 이름…"으로 붙인다.

### ③ set_ops 비교 기준
- 기본은 **exact(부품 + 색상)**, 같은 카드에 **ignore_color 수치를 병기**한다 [초안 권장].
- 결과 수치: 공통 종류(lot) 수, 공통 수량(Σmin), A만·B만 종류 수와 수량
- 표: 공통 부품 상위 N(수량순, 설정 `compare.set_ops_top_n` 기본 15)
- 집계 정의는 T-001 `set_parts_flat`(스페어 제외·미니피그 전개)을 그대로 쓴다.

### ④ DB 카드 본문 형식 (T-012 수치 검증의 기준)
- 사람이 읽을 수 있는 한국어 `키: 값` 줄 형식이다. **모든 숫자는 천 단위 콤마로 표기를 통일**하고, 세트 번호는 `NNNNN-N` 형식으로 쓴다.
  ```
  [DB] 세트 75257-1 Millennium Falcon
  공식 부품 수: 1,328개 (부품 목록 집계 1,351개 — 원본 불일치)
  출시 연도: 2019
  서브테마: Star Wars
  미니피그(6): Boolio, C-3PO, Chewbacca, Finn, Lando Calrissian, R2-D2
  ```
- `title`: 카드 종류별 제목 (예: "세트 정보 · 75257-1", "부품 비교 · 75257-1 vs 75375-1")
- `url`: Rebrickable 세트 페이지. 비교 카드는 첫 세트 URL을 쓴다.
- `license`: "Rebrickable"
- `item_id`: 대상 세트 번호(여러 개면 콤마로 잇는다)
- 공식 부품 수와 집계 합이 다르면(T-002 `count_mismatch`) 둘 다 쓴다.

### ⑤ 템플릿 답변 구조
```python
@dataclass
class TemplateAnswer:
    answer: str                 # [근거 N] 포함 한국어 문장 (1~3문장)
    cards: list[Card]           # 인용된 DB 카드 (n은 1부터)
    tables: list[dict]          # UI용 {"title", "columns", "rows"} — 부족 부품표·공통 부품표·비교표
    warnings: list[str]
```
- build 분석: "75257-1을 만들려면 138개(41종)가 부족합니다. 커버리지 89.6% (exact) [근거 1]" + 부족 부품 표(부품 번호·이름·색상·필요·보유·부족)
- build 추천: "부족이 가장 적은 세트는 …입니다. [근거 1]" + 추천 표(세트·연도·부족 개수·종류·커버리지)
- 예외 문구
  - 없는 세트 → "데이터에 없는 세트 번호입니다" + 후보 (T-002 `SetNotFound`)
  - 부품 목록 없음 → "부품 목록이 없는 세트입니다" (`NoInventory`)
  - 컬렉션 없음 → 등록 안내

## 인터페이스 계약
```python
# db/queries.py
@dataclass(frozen=True)
class SetFact: set_num: str; name: str; year: int; num_parts: int; agg_parts: int
               subtheme: str; scope: str | None; minifigs: list[tuple[str, int]]; entities: list[str]
def set_fact(conn, set_num: str) -> SetFact                 # SetNotFound 전파
@dataclass(frozen=True)
class FilterSpec: year_from: int | None = None; year_to: int | None = None
                  parts_min: int | None = None; parts_max: int | None = None
                  subtheme: str | None = None; minifig: str | None = None   # 미니피그 짧은 이름 부분 일치
                  has_minifig: bool | None = None; name_keywords: tuple[str, ...] = ()
                  scopes: tuple[str, ...] = ("core",); sort: str = "year"; order: str = "asc"; limit: int = 50
def filter_sets(conn, spec: FilterSpec) -> tuple[list[SetFact], int]    # (결과, 전체 건수) — 정렬 마지막 키 set_num
@dataclass(frozen=True)
class SetOps: a: str; b: str; mode: str; common_lots: int; common_qty: int
              only_a_lots: int; only_a_qty: int; only_b_lots: int; only_b_qty: int
              common_lots_ignore_color: int; top_common: list[tuple[str, int | None, str, int]]
def set_ops(conn, a: str, b: str, mode: str = "exact") -> SetOps
@dataclass(frozen=True)
class VersionCompare: entity: str; rows: list[dict]; excluded: list[tuple[str, str]]; warnings: list[str]
def compare_versions(conn, set_num: str, settings) -> VersionCompare

# rag/db_cards.py
def fact_card(f: SetFact, n: int) -> Card
def set_ops_card(r: SetOps, n: int) -> Card
def compare_card(r: VersionCompare, n: int) -> Card
def analysis_card(r: AnalysisResult, n: int) -> Card          # T-002
def recommend_card(recs: list[Recommendation], mode: str, n: int) -> Card
def filter_card(results: list[SetFact], total: int, spec: FilterSpec, n: int) -> Card

# rag/templates.py
def answer_fact(conn, set_num, question) -> TemplateAnswer
def answer_set_ops(conn, a, b, mode="exact") -> TemplateAnswer
def answer_build_analysis(conn, collection, target, mode) -> TemplateAnswer
def answer_build_recommend(conn, collection, mode, filters) -> TemplateAnswer
```

### 피드백 1차 반영

- 반영 일자: 2026-10-22. 요청한 3건 모두 반영했으며, 위 실데이터 출력 예시 3종도 수정 후 CLI stdout으로 갱신했다. 앞의 378개/57개 테스트 기록은 초기 구현의 검증 이력이고 아래가 최종 검증 결과다.
- 연도·표 표시:
  - fact·비교·추천 카드, 필터의 연도 하한/상한, fact 답변 및 CLI 표에서 연도를 `2017`처럼 표시한다. 부품 수·수량의 `7,541` 표시는 유지한다.
  - 표는 `title`, `columns`, `rows`, `formats`를 반환한다. `formats`는 열 이름을 키로 하며 `year`는 콤마 없는 연도, `count`는 천 단위 콤마 수량, `percent`는 소수점 한 자리 퍼센트다. 지정하지 않은 열은 원문/식별자 그대로 표시한다.
  - `rows`의 연도·수량은 int를 유지한다. 추천 커버리지는 planner의 0~1 float 비율을 보존하며, 예를 들어 `0.52`는 CLI에서 `52.0%`로 표시한다. 오류 후보 표는 빈 `formats`를 제공한다. UI 파일은 변경하지 않았다.
- Windows 출력:
  - `main()` 시작 시 stdout/stderr를 UTF-8로 재설정한다. `reconfigure`가 없거나 지원되지 않는 스트림은 그대로 사용한다.
  - 설정·DB 조회 단계만 질의 오류 처리로 감싸고, 렌더링·JSON 변환·출력은 밖에서 수행한다. 출력 중 UnicodeEncodeError를 질의 실패로 바꾸지 않는다.
  - `PYTHONIOENCODING=cp949`인 실제 서브프로세스로 setops/compare/build-analyze를 실행해 종료 코드 0과 UTF-8 출력을 검증했다. cp949 도움말·오류 stderr, 재설정 불가 스트림, 출력 오류 전파도 확인했다.
- 검색 기본 범위:
  - `config/settings.yaml`에 `search.default_scopes: ["core", "compare_only"]`를 추가했다.
  - `FilterSpec.scopes`는 default_factory로 객체 생성 시 설정을 읽으며 CLI의 생략된 `--scope`도 같은 기본값을 사용한다. 명시한 core/compare_only/빈 목록은 그대로 존중한다. 기존 planner 추천 기본 범위는 유지한다.

1. **[결함] 연도에 천 단위 콤마가 붙는다.**
   - 카드 본문 `출시 연도: 2,017`, 판본 비교 행 `출시 연도: 2,000`, 필터 카드 연도 하한·상한, CLI 표의 연도 열 `2,015`
   - 수정: **연도는 콤마 없이** 쓴다 (`2017`). 콤마 통일은 수량·부품 수에만 적용한다.
   - 표 데이터의 `rows`는 원시값(int)을 유지하고, 표에 열별 표시 형식을 추가한다 (예: `{"title", "columns", "rows", "formats": {"연도": "year", "공식 부품 수": "count", "커버리지": "percent"}}`). CLI 렌더러는 이 형식을 따른다. UI(M5)도 같은 형식을 쓴다.
   - 테스트: 카드 본문·CLI 출력에 `2,0` 형태의 연도가 없음, 수량은 콤마 유지
2. **[결함] Windows 콘솔(cp949)에서 CLI가 "질의 실패"로 끝난다.**

   - 수정: `main()` 시작 시 `sys.stdout`/`sys.stderr`를 UTF-8로 재설정한다 (`reconfigure(encoding="utf-8")`, 실패하면 무시). 질의 실패 예외 처리는 질의 단계만 감싸고 출력 단계와 분리한다.
   - 테스트: cp949 출력 스트림을 흉내 낸 경우에도 종료 코드 0
