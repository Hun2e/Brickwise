## 목표
질문이 들어오면 다음 흐름으로 **사전 수집에 없는 근거 문서를 보충**한다.
1. P1이 선택 세트와 질문으로 검색어를 만든다.
2. 처음 보는 검색어만 위키백과에서 검색한다.
3. P2가 후보 중 수집할 문서를 고른다.
4. 고른 문서를 수집·청킹·색인하고, 선택 세트와 연결한다.

같은 세트의 같은 질문은 두 번째부터 외부 호출 없이 끝나야 한다. 이 흐름은 T-008(retrieve 노드)이 질문마다 호출한다.

## 실측 근거 (PM, 2026-10-21) — 미매핑 세트 3개로 P1(p1-v1) → 위키 검색 실행
| 세트 · 질문 | P1 검색어 (요약) | 위키 검색 결과 |
|---|---|---|
| 75076-1 Republic Gunship · "영화에서 어떤 역할?" | `'LEGO Star Wars "Republic Gunship" 75076-1 set'` 등 4개 | 2개 검색어는 **0건**. 나머지는 Republic Commando(게임)·Bounty Hunter(게임)·**List of Star Wars air, aquatic, and ground vehicles** |

| 75357-1 Ghost & Phantom II · "어떤 작품에 나와?" | `'"Ghost & Phantom II" 75357-1'` 등 | 3개 검색어가 모두 시리즈 문서뿐. 마지막에서 **Star Wars Rebels**, Rebel Alliance, Allegiance(소설), Twin Suns |

- 결론
  1. **p1-v1 검색어는 위키 전문 검색에 맞지 않는다.** 세트 번호, 따옴표, LEGO 같은 수식어가 붙어 결과가 0건이거나 시리즈 문서로 쏠린다.
  2. 후보에 게임·소설이 섞인다 → P2 선별이 필수다.
  3. 일부 기체는 목록 문서만 있다.
  4. P1 지연은 1.9~4.8초다.

## 설계 (검토 포인트 ①~⑥)

### ① 질문 시점 문서의 보존 (T-006과의 충돌 해결) ★
- 현재 T-006 `doc_sets()`는 `set_entities`만 보고, `index_docs.py`는 대상에 없는 문서를 **삭제**한다. 그래서 질문 시점에 수집한 문서는 다음 `index_docs` 실행 때 지워진다.
- 해결: `collect.sqlite`에 `question_links(set_num, doc_id, wiki_title, lang, query, selected_reason, created_at, PK(set_num, doc_id))`를 둔다.
  - `doc_sets()` = `set_entities` 기반 ∪ `question_links` 기반 (둘 다 전체 재계산)
  - `index_docs.py`의 대상 = 매핑 문서 ∪ 연결 문서
- 저장 위치를 `collect.sqlite`로 한 이유: `lego.sqlite`는 적재 때 교체되고, `user.sqlite`는 사용자 컬렉션 전용이기 때문이다.
- 청크 메타 `entity_kind`
  - 질문 시점 문서는 `question`
  - 목록 문서는 `list` (제목이 `List of`로 시작)

### ② P1 v2 — 위키 검색용 검색어
- 지시
  - 위키백과 **검색창에 넣을 짧은 키워드**(2~5단어)를 만든다.
  - 세트 번호·"LEGO"·따옴표는 쓰지 않는다.
  - 기체·캐릭터·작품·사건 이름 위주로 쓴다.
- 첫 검색어는 세트의 핵심 대상이다 (예: Republic Gunship → `Republic attack gunship`). F2003의 "선택 항목 자체 문서 포함"에 대응한다.
- `queries` 최대 3개, `purpose` 최대 40자 (T-004 후속: 출력 토큰·지연 축소)
- `en_terms`는 유지한다 (T-008 질의 확장에 사용).
- PM 실측 단계에서 v1 vs v2를 같은 질문으로 비교한다 (0건 비율, 관련 후보 수, 지연).

### ③ P2 — 후보 선별
- 입력: 세트명, 질문, 후보 목록(`id`, 제목, 스니펫 150자, 언어). 이미 색인된 문서는 후보에서 뺀다.
- 출력: `CandidateSelection{selected: [{id, reason(≤40자)}]}`, 최대 `collection.max_docs_per_question`개
- 지시
  - 질문에 답할 근거가 될 **서술 문서**를 고른다.
  - 비디오 게임·소설·코믹스·인물(배우) 문서는 질문이 그것을 묻지 않는 한 제외한다.
  - 관련 후보가 없으면 빈 배열을 돌려준다.
- 목록 문서(`List of …`)는 질문 시점에는 **허용**한다 (일부 기체는 목록 문서만 있음, 실측). 이 문서는 `entity_kind=list` 태그로 색인한다.
  - T-005에서는 목록 문서를 매핑에서 제외했다. 그 결정은 "모든 세트에 미리 붙이지 않는다"는 의미로 유지되고, 질문 시점에 근거로 고르는 것은 별개로 본다.

### ④ 실행 조건과 캐시 (F2004 · NF2002)
- P1은 질문마다 실행한다 (검색어 확장 결과를 T-008도 쓴다). 같은 (set_num, 질문, p1 버전)은 LLM 응답 캐시로 재사용한다.
- 위키 검색은 `fetch_log.queried("wikipedia-search", q)`가 거짓인 검색어만 한다 → **이미 수집한 검색어는 다시 검색하지 않는다.**
- P2는 새 후보가 있을 때만 호출한다.
- 수집은 T-003 `ensure_doc`(판번호 캐시)을 쓴다.
- 결과적으로 같은 세트·같은 질문의 2회차 외부 호출은 0이어야 한다 (P1은 캐시 적중).
- LLM 응답 캐시: `collect.sqlite`의 `llm_cache(key, prompt_version, response_json, created_at)`. 키는 sha256(프롬프트 버전 + 입력)이다.

### ⑤ 시간 예산과 진행 상태 (F2012 · NF2001)
- 단계별 진행 이벤트를 콜백으로 낸다: `extracting_queries → searching(q) → selecting → fetching(title) → indexing → done | skipped(cached)`. T-008·UI가 그대로 표시한다.
- 시간 예산 `collection.question_time_budget_sec`(기본 30초): 넘으면 남은 수집을 건너뛰고 이미 확보한 근거로 진행한다. 결과에 `partial=True`를 표시한다.
- 실측 기준: P1 약 2~5초, 검색어당 약 0.5초, P2 약 2초 [추정], 문서당 수집 약 1.5초, 문서당 색인 약 1~3초 [추정].

### ⑥ 언어
- 검색 언어는 P1 `queries[].lang`을 따른다. 실측상 99%가 영어다.
- 수집한 영어 문서에 한국어 링크가 있으면 T-006과 동일하게 한국어 문서도 수집해 같은 연결을 단다. 설정 `collection.question_include_korean`(기본 true)로 끌 수 있다.

    set_num: str; queries: list[SearchQuery]; en_terms: list[str]

                         on_event: Callable[[str, dict], None] | None = None) -> CollectResult
    # 실패 정책: P1 실패 → 세트명만으로 대체 검색어 1개, P2 실패 → 후보 상위 1개(시리즈·게임 문서 제외 규칙) 선택,
    # 외부 오류 → partial=True로 반환 (예외를 UI까지 올리지 않음, MissingApiKey는 그대로 전달)

def link_question_doc(self, set_num, doc_id, wiki_title, lang, query, reason) -> None

## 테스트 (네트워크 없이)
- P1 v2 프롬프트: 지시문에 세트 번호·따옴표 금지와 3개 제한이 있고, 첫 검색어 규칙이 있음. v1 선택도 가능
- 수집 흐름 (가짜 모델·가짜 수집기·FakeEmbedding)
  - 정상 흐름: P1 → 검색 → P2 → 수집 → 색인. 이벤트 순서
  - 2회차: 같은 질문 → P1 캐시 적중, 검색 0회, P2 0회, 수집 0회
  - 이미 색인된 후보는 P2 입력에서 빠짐
  - P2 빈 배열 → 수집 없음, 정상 종료
  - P1·P2 파싱 실패 → 대체 경로
  - 시간 예산 초과 → `partial=True`
- `question_links`
  - 링크 저장 후 `doc_sets()`에 세트가 포함됨
  - **`index_docs` 재실행 후에도 질문 시점 문서가 삭제되지 않음** (① 회귀 방지)
  - 매핑 세트와 질문 링크 세트의 합집합
- 목록 문서 `entity_kind=list`, 질문 시점 문서 `entity_kind=question` 태그
