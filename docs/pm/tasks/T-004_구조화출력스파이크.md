## 목표
Router와 P1(검색어 추출) 프롬프트가 GMS(`gpt-5.4-nano`)에서 **파싱 가능한 JSON을 얼마나 안정적으로** 돌려주는지 측정한다. 측정 결과로 구조화 출력 방식과 재시도·대체 정책을 확정한다. 이 작업의 코드(LLM 팩토리, 구조화 호출 래퍼, 스키마)는 이후 RAG 코어가 그대로 쓴다.

## 역할 분담 (중요)
- **Codex**: 코드와 오프라인 테스트만 작성한다. Codex 샌드박스는 네트워크와 키를 쓸 수 없으므로 **실제 GMS 호출을 실행하지 않는다.** `.env`를 열거나 출력하지 않는다.
- **PM**: 키가 있는 환경에서 `scripts/spike_structured.py`를 실행하고 결과를 해석한다.

## 범위
- 포함
  1. LLM 팩토리: settings의 `llm` 섹션 + 환경변수 `GMS_KEY`로 `ChatOpenAI`·`OpenAIEmbeddings` 생성

  3. 프롬프트: Router, P1 (버전 문자열 포함)
  4. 구조화 호출 래퍼: 여러 방식 + 재시도 + 텍스트 JSON 추출 대체 + 사용량·지연 기록
  5. 스파이크 스크립트와 질문 세트(25문항)
  6. 가짜 LLM 기반 오프라인 테스트
- 제외: 실제 호출 실행, Chroma·검색·생성(P3), UI, planner·db 코드 수정

## 스파이크 스크립트 (`scripts/spike_structured.py`)
- 입력: `eval/spike_questions.jsonl` 25문항. 한 줄 형식은 `{"id", "question", "expected_route", "set_name", "set_num", "has_collection"}`이다. route 7종을 모두 포함하고(종류당 3~4개), 한국어 표현을 다양하게 한다. 세트는 실데이터 세트(예: 75192-1 Millennium Falcon, 75257-1, 75301-1)를 쓴다.
- 실행: `--methods json_schema,function_calling,json_mode --repeat 2 --prompts router,p1`
  - 기본값: 문항 25 × 방식 3 × 반복 2 × 프롬프트 2 = 최대 300회 호출 → `--limit`로 줄일 수 있어야 함
- 출력
  1. `logs/spike_structured_<타임스탬프>.jsonl` (git 제외): 호출별 id, prompt, method, ok, 실제 method, attempts, latency_ms, usage, error_type, 파싱된 값
  2. 콘솔 요약 표: 프롬프트 × 방식별 파싱 성공률, 재시도 비율, text_extract 비율, 평균·p95 지연, 평균 입출력 토큰, Router 정확도(`expected_route` 일치율)와 혼동 상위 3쌍, `temperature` 관련 오류 여부
- 키가 없으면 `MissingApiKey` 안내 문구만 출력하고 종료 코드 2

- 설계 판단과 이유:
  - import와 `--help`는 dotenv를 로드하지 않는다. 모델 팩토리 첫 사용 시에만 1회 로드하고 기존 환경변수를 우선한다. 검증에서는 dotenv를 대체했으므로 실제 `.env` 접근은 없다.
  - SDK 내부 재시도를 0으로 고정하고 구조화 래퍼에서 설정 횟수만큼 재시도하여 호출 횟수·토큰을 관측한다. JSON 복구는 이미 받은 원문을 최신 응답부터 검사하며 추가 API 호출을 하지 않는다. 중첩 JSON·코드 펜스·앞뒤 설명을 처리하고 동일 Pydantic 스키마로 재검증한다.
  - `attempts`는 실제 `invoke` 시도 수이며, 구조화 방식 구성 단계에서 실패하면 0이다. 실패는 `ok=False`, `value=None`, 예외 클래스명만 반환하고 `MissingApiKey`만 전파한다. temperature 오류는 메시지를 보존하지 않고 별도 bool로 기록한다.
  - 사용량은 재시도를 포함해 관측된 토큰을 합산한다. 제공되지 않은 사용량은 0으로 채우지 않으며 콘솔에 관측 수와 N/A를 표시한다. p95는 nearest-rank, Router 정확도는 실패까지 포함한 전체 결과 기준이다. 성공률에는 `text_extract` 성공도 포함하고 그 비율을 따로 표시한다.
  - `method`는 요청 방식, `actual_method`는 성공 방식이며 프롬프트 버전과 반복 번호도 JSONL에 남긴다. 결과를 매번 flush해 중단 시 이전 결과를 보존한다.
  - P1은 자체 세트 검색어를 첫 번째로, 영어 우선·최대 4개로 요청한다. 컬렉션이 없어도 제작 의도는 build 계열로 유지해 이후 호출자가 등록 안내를 할 수 있게 했다.
