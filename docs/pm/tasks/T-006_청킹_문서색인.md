1. T-005가 매핑한 기체·캐릭터·장소 문서와 시리즈 문서를 사전 수집한다.
2. 섹션 우선 규칙으로 청킹한다.
3. Chroma `set_docs` 컬렉션에 **문서당 1벌**로 색인한다. 각 청크의 `sets` 배열에 연결 세트를 둔다.

## 설계 (검토 포인트 ①~⑥)

### ① 사전 수집·색인 대상
- **영어 매핑 문서**: `set_entities`의 고유 `wiki_title` (현재 52개)
- **시리즈 문서**: settings `wikipedia.seeds` 중 시리즈 문서(`Lego Star Wars` 영어, `레고 스타워즈` 한국어) → `scope="series"`
- **한국어 문서**: 영어 매핑 문서의 한국어 언어 링크 문서. 같은 엔티티로 보고 같은 `sets`를 단다.
  - T-003 실측: 한국어 문서는 영어판의 2.5~47% 길이다.
- 초안: 세 가지 모두 포함한다.

### ② 일반 집단 문서 처리
- `kind: group` 문서(Galactic Empire, Jedi, Sith, Droid, Clone trooper, Stormtrooper, First Order, Resistance, Rebel Alliance, Wookiee)는 크고 일반적이다. 그런데 연결 세트가 많다 (Galactic Empire 29세트 — `\bimperial\b` 규칙 때문).
- 위험: 한 세트에 group 문서 청크가 수십 개 붙으면, 정작 기체·캐릭터 문서 청크가 검색에서 밀릴 수 있다.
- 선택지
  - (a) 그대로 포함
  - (b) 포함하되 메타 `entity_kind="group"`을 달아 두고 T-008·M6에서 가중치나 개수 제한으로 조정 **[초안 권장]**
  - (c) group 문서는 색인 제외

### ③ 청킹 규칙
- 섹션 단위로 먼저 나누고, 1,000자를 넘는 섹션만 `RecursiveCharacterTextSplitter(chunk_size, chunk_overlap)`로 자른다. 값은 settings이고 시작값은 1,000/200이다.
- 청크 앞에 `[{문서 제목} › {섹션 경로}]` 머리말을 붙인다. 섹션 경로는 상위 섹션 제목을 ` › `로 잇는다 (예: `[Lego Star Wars › Construction sets › Minifigures]`).
  - 머리말은 임베딩 텍스트에 포함한다. 청크 크기 계산에는 본문만 넣는다.
- 짧은 섹션 병합: 실측상 200자 미만 청크가 9.7%다.
  - (a) 40자 미만만 다음 섹션에 병합 (ADR-008 값)
  - (b) **200자 미만은 같은 상위 섹션 안의 인접 섹션과 병합, 상한 1,000자는 유지** [초안 권장 — 짧은 청크는 임베딩 의미가 약하다]
- 결정적: 같은 문서·같은 설정이면 항상 같은 청크와 같은 ID가 나와야 한다.

### ④ ID와 `sets` 배열 (F2005 덮어쓰기 대응)
- 청크 ID
  - 기체 문서: `entity:{doc_id}:{seq:04d}`
  - 시리즈 문서: `series:{doc_id}:{seq:04d}`
  - 예: `entity:wp-en:23861227:0004`
- `sets` 배열은 **증분으로 덧붙이지 않는다.** 색인할 때마다 `set_entities` 전체에서 문서별 연결 세트를 다시 계산해 통째로 넣는다. 그러면 "새 세트를 연결하다가 기존 목록을 잃는" 문제가 구조적으로 생기지 않는다. 매핑 규칙이 바뀌어 연결이 끊긴 경우도 반영된다.
  - 한국어 문서의 `sets` = 대응 영어 문서의 `sets`
  - 시리즈 문서는 `sets=[]`, `scope="series"`
- 테스트로 고정: 세트 A·B가 같은 문서를 공유할 때 A만 다시 매핑해도 B가 `sets`에 남아 있음, 청크 ID 충돌 없음.

### ⑤ 동기화 (멱등·변경 반영)
- 문서별 `revid`를 청크 메타에 저장한다.
- 같은 revid이고 청킹 설정 해시가 같고 `sets`도 같으면 → 건너뛴다 (임베딩 호출 없음).
- `sets`만 바뀌었으면 → 메타데이터만 갱신한다 (Chroma `update`, 임베딩 재계산 없음).
- revid나 청킹 설정이 바뀌었으면 → 해당 doc_id 청크를 모두 삭제하고 다시 넣는다.
- 대상에서 빠진 문서 → 청크를 삭제한다.
- 리포트: 문서 수, 청크 수, 신규·갱신·메타만 갱신·삭제 수, 임베딩 API 호출·캐시 적중, 소요 시간.

### ⑥ 청크 메타데이터
`source_type="wikipedia"`, `scope`(entity|series), `doc_id`, `title`, `url`, `license`, `attribution`, `lang`, `revid`, `section_path`, `seq`, `sets`(list[str]), `entity`(영어 wiki_title), `entity_kind`(vehicle|character|group|place|media|series), `collected_at`, `chunk_config`(예: "1000/200/200")

### 설계 판단과 이유

- 섹션 깊이 스택으로 경로를 구성하고, 부모 섹션의 등장 위치까지 비교하여 다른 부모 영역의 짧은 조각이 병합되지 않도록 했다. 병합한 청크의 `section_path`는 각 원래 경로를 ` | `로 연결한다. 머리말은 임베딩 본문에 포함하지만 `char_len`과 크기 제한에는 포함하지 않는다.
- 설정 해시는 크기·중복·최소 길이·머리말 여부를 모두 포함한다. 청크 ID는 문서 전체에서 순서대로 `{scope}:{doc_id}:{seq:04d}`를 사용한다.
- 연결 세트는 매번 전체 `set_entities`를 읽고 정렬·중복 제거한다. 여러 영어 제목이 같은 문서로 연결되는 경우에도 본문은 한 벌로 모으고 연결 세트는 합집합을 적용한다.
- 기본 `tag` 정책은 `entity_kind="group"`을 보존한다. `include`도 원래 종류 정보를 유지하며 `exclude`는 해당 영어 문서와 한국어 파생 대상을 제외한다. 한국어 링크 옵션을 꺼도 명시적인 한국어 시리즈 시드는 유지한다.
- 동일한 본문·판번호·설정은 임베딩을 생략한다. 메타 변경은 Chroma `update`만 사용하며, 본문 교체는 벡터를 먼저 준비한 후 삭제·upsert하여 임베딩 실패로 기존 문서가 사라지지 않게 했다. 제외 문서는 대상 처리 성공 뒤 삭제한다.
- 요청 제목을 `mapped:{lang}:{title}` 형태의 기존 `fetch_log.query`에 남겨 리다이렉트 후에도 로컬에서 대응 문서를 찾는다. 별도 스키마 수정 없이 판번호별 언어 링크 캐시를 재사용한다. 색인 CLI는 네트워크로 수집을 보완하지 않고, 필요한 본문·언어 링크가 없으면 기존 색인을 유지하며 실패한다.
- **Chroma 1.5.9 제약:** 빈 배열 메타데이터는 `Expected metadata list value for key 'sets' to be non-empty`로 거부된다. 논리적 `sets=[]`는 저장 시 `sets` 필드를 생략하고 읽을 때 `metadata.get("sets", [])`로 해석한다. 시리즈는 `scope="series"`를 항상 저장하므로 계약된 `$or` 조회가 동작한다. 연결이 모두 사라지면 `update`의 `None`으로 기존 필드를 제거한다. JSON 문자열이나 가짜 세트 번호를 넣지 않는다.
- 통계의 `new`, `updated`, `metadata_updated`, `deleted`, `skipped`는 문서 수이며 `chunks`, `deleted_chunks`는 청크 수다. `api_calls`, `cache_hits`, `embedded`는 해당 동기화 호출 전후 임베딩 캐시 통계 차이다.
