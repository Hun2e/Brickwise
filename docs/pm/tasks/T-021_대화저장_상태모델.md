# T-021 통합 대화 저장·상태 모델·마이그레이션

- 상태: 완료 (2026-10-23)
- 관련 요구사항: F2009(항목별 대화 기록 분리), NF2005, ADR-018 ②⑥⑦
- 선행 작업: T-020 커밋(a864526). 설계: `docs/planning/05_대화UX설계.md` §3.1·§3.2·§5

## 목표
대화 단위(`conversation_id`)의 저장소, 구조화 대화 상태(낙관적 버전), 턴–세트 연결(`turn_subjects`), 세트별 기록 조회를 만든다. 기존 `user.sqlite`를 **비파괴로** 이관한다. 이 작업은 저장 계층만 다루고, 채팅 흐름·API·화면은 바꾸지 않는다.

## 범위
- 포함
  1. `src/rag_service/db/user_schema.sql`: 새 테이블 `schema_meta`, `conversations`, `conversation_state`, `turn_subjects`, `chat_requests`(사용은 T-024), `collection_events`(사용은 T-022). 장부 테이블은 만들기만 한다.
  2. `src/rag_service/services/migrations.py`(신규)
     - `migrate(path) -> MigrationReport`: 백업 복사 → 테이블 생성 → 열 추가(`conversation_turns.conversation_id/request_id/kind/state_version`, `collections.version`) → 레거시 이관 → `schema_meta` 기록
     - 멱등이다. 원 행은 삭제·변경하지 않는다(열 채우기만 한다).
  3. `src/rag_service/services/dialogue_state.py`(신규): `DialogueState`·`Subject`·`ShownList`·`Pending` 데이터클래스, JSON 직렬화·검증, 초기화 규칙 함수(`on_new_subject`, `on_clear_subject`, `on_new_list`, `on_pending` …)
  4. `src/rag_service/services/conversations.py`
     - `ConversationRepo`: `create`, `list(uid)`, `get(uid, cid)`(턴 + 상태), `delete`, `load_state` / `save_turn_with_state(...)`(한 트랜잭션에서 턴·`turn_subjects`·상태를 저장하고 version 충돌을 확인), `set_history(uid, set_num)`(role ∈ primary·compared), `context_turns(uid, cid, subject, n)`(같은 대상 primary 턴만)
     - 기존 `ConversationStore` API는 그대로 둔다(구 화면·테스트 호환).
  5. 레거시 이관 규칙(05 §5.4): `(uid, thread)`마다 대화 1개, 세트 thread → `turn_subjects(primary)` + 상태 `subject=그 세트(source=ui)`, explore·collection → 대상 없음. 제목 규칙.
  6. 상태 점검(`services/status.py`): 마이그레이션 필요 여부와 실패 안내 한 줄
  7. 테스트(신규 `tests/test_dialogue_store.py`, `tests/test_migrations.py`)
- 제외: 컬렉션 변경 서비스(T-022), 해석기(T-023), `chat_turn`·API·화면(T-024·T-025)

## 인터페이스 계약

```python
# services/dialogue_state.py
@dataclass(frozen=True)
class Subject: set_num: str; source: Literal["explicit","list","card","ui"]; turn_id: int | None
@dataclass(frozen=True)
class ShownList: kind: Literal["search","recommend","candidates"]; turn_id: int | None
                 items: tuple[str, ...]; spec: dict | None = None; rec: dict | None = None
@dataclass(frozen=True)
class Pending: kind: Literal["target","quantity","confirm"]; options: tuple[str, ...]; request: dict
@dataclass(frozen=True)
class DialogueState:
    subject: Subject | None = None; last_list: ShownList | None = None
    compare: tuple[str, ...] = (); mode: Literal["exact","ignore_color"] = "exact"
    pending: Pending | None = None
    def to_json(self) -> str: ...
    @classmethod
    def from_json(cls, raw: str | None) -> "DialogueState": ...   # 손상·구버전이면 빈 상태 + 경고
# 초기화 규칙 (05 §3.3 표와 1:1)
def with_subject(s, subject) -> DialogueState      # compare·pending 비움, last_list 유지
def cleared(s) -> DialogueState                     # subject·pending·compare 비움
def with_list(s, shown) -> DialogueState            # last_list 교체, pending 비움
def with_pending(s, pending) -> DialogueState

# services/conversations.py
class StateConflict(Exception): ...
class ConversationRepo:
    def create(self, uid: str, title: str | None = None) -> str
    def list(self, uid: str) -> list[dict]          # {id, title, updated_at, subject, turns}
    def get(self, uid: str, cid: str) -> dict       # {id, title, turns: [Turn+subjects], state, version}
    def save_turn_with_state(self, uid, cid, *, question, response: dict, kind, subjects: list[tuple[str,str]],
                             state: DialogueState, expected_version: int, request_id: str | None) -> Turn
    def set_history(self, uid: str, set_num: str) -> list[Turn]      # primary·compared, 시간순
    def context_turns(self, uid: str, cid: str, subject: str | None, n: int) -> list[Turn]
    def delete(self, uid: str, cid: str) -> int
```

## 완료 기준 (DoD)
- [ ] 레거시 DB 사본(현재 스키마 + 세트·explore·collection thread 턴 + 컬렉션)에 `migrate`를 **2회** 실행하면 두 번째 실행에서 변경 0이다. 원 행 수·내용은 그대로, 백업 파일이 생긴다.
- [ ] 이관 뒤 세트 thread 대화의 턴 수가 기존 thread 턴 수와 같다. `set_history("A-1")`에 기존 A-1 턴이 모두 있고, B-1 턴은 없다.
- [ ] F2009 기준 (a)(e): A의 세트별 기록에 B가 primary인 턴이 0건이다. compared 턴은 포함되며 표시용 표식이 있다. listed만 연결된 턴은 제외한다.
- [ ] `context_turns(subject=A)`는 같은 대화의 A primary 턴만 최근 n개 돌려준다.
- [ ] `save_turn_with_state`는 version이 다르면 `StateConflict`를 내고 턴을 저장하지 않는다(원자성). 동시 저장 20회에서 버전이 단조 증가한다.
- [ ] `DialogueState` JSON 왕복과 초기화 규칙이 05 §3.3 표의 모든 칸과 일치한다(매개변수화 테스트).
- [ ] 기존 `ConversationStore` 테스트가 수정 없이 통과한다.

- 설계 판단과 이유:
  - `migrate(path)`는 기존 DB에 대해 명시적으로 실행한다. `ConversationRepo`는 없는 DB만 초기화하며 기존 DB가 미이관이면 안내 예외를 낸다. 현재 채팅 흐름·API·화면의 자동 이관은 넣지 않았다.
  - 백업은 대상 DB 옆 `backup/user-<UTC timestamp>-<uuid>.sqlite`에 SQLite backup API로 생성하여 WAL 커밋도 포함한다. 쓰기 잠금을 잡은 뒤 백업하고, `executescript`의 암묵적 커밋을 피하여 DDL·레거시 이관·버전 기록을 한 트랜잭션으로 처리한다. 백업 실패 시 변경하지 않고, 이관 중 실패하면 스키마와 행을 모두 롤백한다.
  - 원래 여섯 턴 열과 컬렉션 내용은 유지한다. 추가한 열만 채우며 세트 이름은 설정의 참조 DB를 읽기 전용으로 조회한다. 이름 조회가 불가능하면 세트 번호를 제목으로 보존한다. 구 저장소에서 나중에 추가한 미이관 턴은 재실행 시 기존 레거시 대화에 합류한다.
  - 상태 JSON의 `schema_version=1`과 DB의 낙관적 `version`은 별개다. 손상·미지원 형식은 원문을 로그에 노출하지 않는 경고와 빈 상태로 복원하며, 낙관적 버전은 유지한다. 목록의 순서는 JSON 왕복에서도 보존한다.
  - `load_state(uid, cid)`는 `(DialogueState, version)`을 반환한다. `get`의 턴은 `Turn` 객체이며 `subjects`와 `comparison_label`(`비교: A-1·B-1`)을 제공한다. `delete`는 삭제한 턴 수를 반환하고 다른 사용자/없는 대화는 `KeyError`로 처리한다.
  - 저장은 `BEGIN IMMEDIATE`와 기대 버전 조건부 갱신으로 원자성을 보장한다. 충돌·중복 request_id·연결 삽입 실패 시 턴/상태/연결 모두 롤백한다. 20개 동시 요청은 충돌 후 재조회하여 버전 1~20으로 저장되며, 같은 기대 버전의 두 요청 중 하나만 성공한다. 요청 재전송 처리와 장부 사용은 T-024 범위다.
  - 한 턴의 primary는 하나이며 primary와 compared의 혼합을 거부한다. 비교 턴은 양쪽을 compared로 연결한다. 세트별 기록은 primary/compared만, 모델 문맥은 같은 사용자·대화·대상의 primary만 반환한다. listed는 두 조회에서 제외한다.
  - 새 의존성은 없다. 이관 필요 안내만으로 기존 UI의 `can_chat`을 차단하지 않아 T-024 전환 전의 구 흐름을 유지한다.
