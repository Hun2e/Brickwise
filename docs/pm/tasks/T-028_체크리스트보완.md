# T-028 셀프 체크리스트 보완 — 버린 후보 표시, 재색인 중단 안전성

- 관련 요구사항: F2003·F2004(후보 선별 결과 확인), F2005·F2002(재색인), NF2006(외부 호출 재시도)
- 선행 작업: T-027 (커밋 6331c62)

## 배경
셀프 체크리스트 3번 "후보 선별에 따라 색인된 문서와 버려진 문서가 구분된다"를 실행해 보니, `scripts/ask_collect.py` 출력에 선택 문서(`selected`, 사유 포함)만 있고 버린 후보는 개수(`candidates: 5`)만 나온다. 제목·사유가 없어 구분을 확인할 수 없다.
5번 "청크 설정을 바꿔 재색인"을 실행하는 동안 GMS 임베딩이 502를 두 번 반환했다. `sync_set_docs`는 문서 단위로만 원자적이라, 중간에 실패하면 일부 문서는 새 설정, 나머지는 옛 설정인 채로 컬렉션이 남았다(3,629 → 2,763). 다시 실행하면 캐시 덕분에 이어서 완료된다.

## 범위
- 포함
  1. **버린 후보 기록**: `rag/collect.py`의 `CollectResult`에 `rejected: list[tuple[str, str, str]]`(id, 제목, 사유)를 추가한다. 사유는 P2가 고르지 않음 → "선별되지 않음", 도메인 보호 장치에서 탈락 → "도메인 단서 없음", 문서 수 상한 초과 → "문서 수 상한 초과"처럼 실제 원인별로 구분한다. 후보 제목은 `selected` 항목에도 보이도록 `selected`를 (id, 사유) 그대로 두되 결과에 `selected_titles`(id → 제목)를 추가한다(기존 필드 형식 유지).
  2. **진행 이벤트**: `selecting` 단계가 끝나면 `selected`(제목 목록)와 `rejected_count`를 담은 이벤트를 하나 더 보낸다(예: `selected` 이벤트). `services/progress.py`는 이를 "문서 수집" 단계의 상세 `"선택 1 · 제외 4"`로 변환한다. 화면(웹·Streamlit)은 기존 처리 과정 목록에 그대로 나오므로 UI 코드 변경은 필요 없을 것이다(필요하면 최소 수정).
  3. **`scripts/ask_collect.py`**: JSON 결과에 위 필드가 그대로 포함되게 한다(`asdict`). 별도로 사람이 읽기 쉬운 표 출력 옵션 `--table`을 추가해 "검색어 / 선택(제목·사유) / 제외(제목·사유)"를 나란히 보여 준다.
  4. **재색인 중단 안전성**: `vectorstore/doc_index.py sync_set_docs`를 두 단계로 바꾼다 — ① 바뀐 문서 전체의 벡터를 먼저 계산(캐시에 저장)하고, ② 모두 성공했을 때만 삭제·upsert를 적용한다. ①에서 실패하면 컬렉션은 그대로이고 예외를 다시 던진다(이미 계산한 벡터는 임베딩 캐시에 남아 재실행 시 재사용). 메모리 사용이 문제되지 않는 규모(문서 140개·청크 4천 개)임을 결과 보고에 적는다.
  5. **임베딩 재시도**: 임베딩 API의 일시 오류(5xx·429·연결 오류)를 `config/settings.yaml`의 값(예: `index.embed_max_retries: 3`, `index.embed_retry_backoff_sec: 2`)으로 재시도한다. 배치 단위로 재시도하며 4xx(429 제외)는 재시도하지 않는다. 위치는 `vectorstore/embed_cache.py`(캐시 미스 배치 호출부) 또는 `llm.py get_embeddings`의 클라이언트 설정 중 테스트하기 쉬운 쪽.
  6. 테스트: 버린 후보 사유 구분(P2 미선택·도메인 탈락·상한 초과), 이벤트→단계 상세 변환, ①단계 실패 시 컬렉션 무변경(가짜 임베딩이 N번째 배치에서 예외), 일시 오류 재시도 후 성공·영구 오류는 재시도 없음.

  - 운영 `data/`(chroma, collected, user.sqlite) 수정 금지. 실측은 PM이 복사본으로 한다.
  - `eval/*.jsonl` 수정 금지. 웹 UI 구조 변경 금지.

  3. 색인 보존: 벡터를 모두 준비한 뒤 update·delete·upsert·prune을 적용한다. 단위 테스트(N번째 배치 실패, 502 재시도 소진)로 ID·본문·메타·벡터 보존과 캐시 재사용을 확인했다.
  4. 보장 범위: Chroma 반영 도중 강제 종료되는 경우의 롤백은 범위 밖이다. 그렇게 되어도 재실행하면 캐시로 수렴한다. 제출 범위에서는 허용한다.
- 참고(후속 아님): `Retry-After`에 상한이 없다. GMS가 큰 값을 주면 대기가 길어질 수 있지만 현재 관측된 적은 없다.
