## 목표
UI가 호출할 **단일 진입점** `services/orchestrator.answer()`를 만든다.
1. 라우터가 질문을 7개 경로(fact·filter·set_ops·narrative·compare·build·build_archive)로 분류한다.
2. 규칙 안전장치로 분류를 보정한다.
3. 각 경로를 이미 만든 모듈에 연결한다.
4. 모든 경로가 **같은 응답 형식**을 돌려준다 (M5의 Streamlit·FastAPI가 그대로 사용).

수치 사후 검증(T-012)은 이 응답 형식 위에 붙인다.

## 설계 (검토 포인트 ①~⑥)

### ① 통합 응답 형식 (UI 계약)
```python
@dataclass
class OrchestratorResponse:
    route: str                       # 최종 경로
    route_source: str                # "llm" | "rule:<규칙명>" | "fallback"
    answer: str                      # [근거 N] 포함 본문 (템플릿 또는 P3)
    cards: list[Card]                # 인용된 근거만 (번호 유지)
    tables: list[dict]               # 템플릿 표 (formats 포함)
    set_nums: list[str]              # filter 결과 카드 선택용 / 결합 질의 선택 세트
    needs_input: str | None          # 추가 입력이 필요할 때 안내 (세트 번호·컬렉션)
    warnings: list[str]
    usage: dict; timings: dict
```
- 모든 경로가 이 형식을 돌려준다. Streamlit과 FastAPI(M5)는 이 형식만 그린다.

### ② 라우터 v2 입력 맥락
- 입력: 질문 + **선택 세트**(번호·이름, 없으면 "없음") + **직전 1턴**(질문·경로, 답변 앞 200자) + 컬렉션 유무
- 출력은 v1 필드에 `set_refs`를 더한다: 질문 속 지시어("이 세트·이 기체·그거")가 선택 세트를 가리키면 `"selected"`
- 예시에 실측 오분류 2건을 넣는다.
  - "연도별로 달라졌어" → compare
  - "그거 언제 나왔어?" + 직전 fact → fact
- 버전 `router-v2`. 응답 캐시 키에 맥락을 포함한다.

### ③ 세트 번호 해석 (결정적)
- 순서
  1. 라우터 `set_nums` → `normalize_set_num`
  2. `set_refs` 또는 질문에 지시어가 있으면 선택 세트를 추가
  3. 경로별 필요 수를 채운다
- 경로별 필요 수
  - fact·narrative·build: 1개 (없으면 선택 세트)
  - set_ops: 2개 (1개면 선택 세트를 다른 쪽으로)
  - compare: 1개 (기체 기준 판본 비교의 기준 세트) 또는 기체 이름 → 그 기체의 대표 core 세트
- 해석할 수 없을 때 (번호가 없고 선택 세트도 없음, 없는 번호): **추측하지 않고** `needs_input`으로 되묻는다 ("어느 세트를 말씀하시는지 세트 번호나 이름을 알려 주세요"). 없는 번호는 T-002 `SetNotFound` 후보를 함께 보여 준다.

### ④ 규칙 안전장치 (ADR-012 결정 1 + 실측 보강)
| 규칙 | 조건 | 처리 |
|---|---|---|
| no_collection | build·build_archive인데 컬렉션 없음 | `needs_input` = 보유 세트 등록 안내 |
| no_narrative | build_archive인데 서술 표현(특징·역사·설명·어떤·왜) 없음 | build |
| compare_cue | narrative인데 비교 표현(연도별·판본·달라졌·변천·비교·차이) + 세트/기체 확인됨 | compare |
| two_sets_parts | 세트 2개 이상 + "공통·겹치·같은 부품" | set_ops |
| low_confidence | 라우터 confidence < `router.min_confidence`(0.6)이고 위 규칙 미해당 | narrative (RAG는 근거 없으면 "확인되지 않음"으로 안전) |
- 규칙이 적용되면 `route_source="rule:<이름>"`으로 남긴다.

### ⑤ 경로별 처리
| 경로 | 처리 | 생성 |
|---|---|---|
| fact | T-009 `answer_fact` | 템플릿 |
| set_ops | T-009 `answer_set_ops` | 템플릿 |
| build | 대상 세트가 있으면 `answer_build_analysis`, 없으면 `answer_build_recommend` | 템플릿 |
| filter | T-010 `search_sets` | 카드 목록 + `set_nums` |
| narrative | T-008 `ask(set_num, question, history)` | P3 |
| compare | T-009 `compare_versions` → `compare_card`를 `injected_cards`로 → `ask` | P3 (판본 표는 `tables`로 함께) |
| build_archive | planner 추천 → **선택 기준 추출** → 코드 선택 → 추천·선택 카드를 `injected_cards`로 → 선택 세트로 `ask` | P3 |

- **결합 질의 선택 기준** (ADR-012 결정 4): `SelectionCriteria{sort: "year"|"missing"|"coverage"|"num_parts", order, max_missing: int|None}`를 LLM으로 추출한다 (JSON 키 명시, T-010 교훈).
  - 코드가 추천 결과(상위 `router.build_archive_pool`, 기본 30)에서 `max_missing`으로 거른 뒤 정렬해 1개를 고른다.
  - 기준이 없으면 부족 개수가 가장 적은 세트를 고른다.
  - 결과에 "선택 이유"(예: "부족 20개 이하 중 가장 오래된 세트") 카드를 둔다.

### ⑥ 진행 이벤트·캐시·지연
- 이벤트: `routing → resolving → (경로별: querying | searching | collecting/retrieving/generating) → done`
- 라우터 응답 캐시: T-007 `llm_cache` 재사용 (키 = 프롬프트 본문 + 맥락)
- 지연 목표 [추정]: 템플릿 경로 ≤ 라우터 + 0.5초 / P3 경로 ≤ 라우터 + T-008 수준
